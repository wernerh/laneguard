# Examples

**The public example project with recorded runs does not exist yet.** Nothing in this directory is a recording, a transcript or a result of a real Laneguard run, and none should be presented as one.

## What it will contain

A small public repository, separate from this one, with Laneguard installed and pinned to a commit SHA, and:

- the exact `.laneguard/config.yaml`, `CLAUDE.md`, plan and roadmap the lanes ran against,
- the issues the lanes picked up, the pull requests they opened, and the reviewer verdicts,
- raw run logs and the run history file (`runs.jsonl`) exported unedited from the data branch,
- at least one run in which a gate stopped an action (for example an attempt to edit a protected path), and at least one quiet run,
- the cost of each run as recorded by the tooling.

## How it will be produced

1. Create a throwaway repository on GitHub owned by the maintainer, with a small real task list.
2. Install Laneguard with `/laneguard:init`, run `/laneguard:doctor` until it passes, start in `observe` then `propose` mode.
3. Run real lanes (`/laneguard:run dev`) with a real Anthropic API key and a low budget ceiling.
4. Commit the run logs and history as they are. Failed and quiet runs stay in. Nothing is rewritten, trimmed to look better, or generated by hand.
5. Link the repository from the main README only once it exists.

The eval suite in `../evals/` is separate: it is a repeatable test set, whereas the example project is a narrative demonstration.
